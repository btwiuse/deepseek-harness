# Agent Note: 允许 --host 0.0.0.0 以支持代理前置的 Web 部署

Status: implemented

[English](2026-08-14-allow-all-interfaces-web-bind.md) | 中文

## 问题

`dsh web` 直接拒绝 `--host 0.0.0.0`（"有意暂不支持，出于安全考虑"），默认只绑定 127.0.0.1，因此当时唯一支持的公开暴露方式是让反向隧道前置回环监听。平台原生的公网域名不适用这种方式：Railway 这类代理会连到容器的私网 IP 上的 `$PORT`，而该接口上没有任何监听，于是即使应用本身已启动且回环可达，公网域名仍返回 502。

## 决策

`web-startup` 现在接受 `--host 0.0.0.0` 并绑定所有网络接口。/api 浏览器信任栅栏保持不变，仍然把关访问——Host、Origin 与特权回环钉死的语义与之前完全一致，除非 `--dev` 将其关闭（[浏览器信任边界](../architecture/2026-07-28-api-browser-trust-boundary.md)）。随仓库发布的 `Dockerfile` 现在以 `dsh web --dev --host 0.0.0.0` 启动，使平台代理能够到达容器；`--dev` 得以保留，因为代理前置的部署无法向回环钉死的端点呈现回环 Host。

测试随行为更新：`startup.spec.ts` 断言 `--host 0.0.0.0` 会发布 all-interfaces 主机，built-bin e2e 中针对拒绝行为的断言已删除，`smoke-real.e2e.ts` 会以 `web --host 0.0.0.0` 启动进程，并通过回环与机器 LAN 地址分别抓取 SPA。

## 曾考虑的替代方案

**在容器内做 TCP 转发。** `dsh` 留在 127.0.0.1，由另一个进程把 0.0.0.0:$PORT 转发过去。不采用：多了一个运动部件和端口调配；一旦操作者显式要求绑定所有接口，转发相比栅栏并不能带来额外安全。

**保持回环并强制反向隧道。** 不采用：每个平台原生域名（Railway、Fly）都将永久依赖第三方隧道；显式的 all-interfaces flag 才是更小、更文档化的表面。

**接受 0.0.0.0 但只打警告。** 不采用：栅栏已经把关 /api；操作者点名主机之后，警告只是噪音而非保护。

## 后果

代理前置的部署现在只需一个 flag 即可工作：`dsh web --dev --host 0.0.0.0`，或在无法接受 `--dev` 时改用 `--host 0.0.0.0` 加 `--trusted-host`/`--trusted-origin`。安全姿态由操作者显式选择：绑定所有接口会把应用暴露到网络上，且未开 `--dev` 时，回环钉死的 /api 端点仍要求回环 Host 或已声明的 origin。`dsh web:` 就绪行仍然打印回环 URL，并在绑定 0.0.0.0 时附上 LAN 候选地址。
